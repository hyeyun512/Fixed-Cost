# FC.1 — 고정비 raw data 통합 + 기준정보 반영 + 배부기준 계산

## 이 스킬이 하는 일

4단계로 동작해서 최종 완성된 `edit_{N}월.xlsx`를 한 번에 만든다.

**1단계 (raw 결합)**: 여러 시트로 나뉜 raw data 파일(각 시트는 SAP FBL3N 등에서 뽑은 거래 내역
다운로드 포맷, 시트명은 `본사_XXX` 또는 `법인_XXX` 형태)을 하나의 표로 세로 결합해서 기본 `edit`
시트를 만든다 (환율 반영 포함).

**2단계 (기준정보 반영)**: 같은 작업 폴더의 `기준정보_{N}월.xlsx` 파일(Costcenter/company/통합계정/
계정구분 시트로 구성)을 읽어, Company Code → Company, Cost Center → Cost Ctr Name/대조직/배부조직/
보고용/보고용(re), G/L Account → 소계정/대계정/대계정(re)/구분/분류 열을 추가로 채운다.

**3단계 (배부기준 반영)**: 같은 기준정보 파일의 `배부기준` 시트를 읽어, 테이블 끝(URL 열)에서 한 열
띄고 `배부기준` 열을 새로 만들어 채운다. 또한 보고용이 `주재원`(예: `6.해외법인(주재원)`)인 행은
`본사/법인` 열 값을 `법인`으로 재기재한다.

**4단계 (조정 전표 수기 반영 + 조건부 배부기준/실적 제외 수정 + 열 그룹화)**: 기준정보 파일의
`1차 편집` 시트에 `[조정 전표 추가]` 블록이 있으면, 그 안의 수기 조정 전표들을 edit 시트 맨 끝에
행으로 추가한다 (Text는 항상 `[Manual]`로 시작). 또한 같은 시트에 `[조정 전표 추가]` 마커 없이
조건문 + `예시` 표로만 구성된 섹션(`[제외]`/`[배부]` 태그)이 있으면, 그 조건에 맞는 edit 시트의
당월 실제 행을 찾아 배부기준을 수정하거나 Amount(KRW)를 삭제한다(자세한 내용은 아래 "4단계 확장
규칙" 참고). 그 다음 edit 시트의 A~B, D~G, L, P, S~Y, AB~AD, AF~AG 열을 그룹화한다 — 이 열 그룹화는
조정 전표 유무와 무관하게 매달 항상 적용한다.

사용자가 raw 파일만 첨부해도, 같은 작업 폴더에 `기준정보_{월}월.xlsx`가 있으면 자동으로 찾아 4단계까지
전부 수행한다 (사용자가 별도로 기준정보 파일을 언급하지 않아도 된다).

## 최종 컬럼 순서 (35열: 기본 33열 + 빈 열 1개 + 배부기준)

```
본사/법인, Company Code, Company, Posting Date, Order, Document Number, Document Type,
Cost Center, Cost Ctr Name, 대조직, 배부조직, 보고용, 보고용(re),
G/L Account, 소계정, 대계정, 대계정(re), 구분, 분류,
Posting Key, Document currency, Amount in doc. curr., Local Currency,
Amount in local currency, Currency, Amount(KRW),
Text, Reversed with, Reference key 1, Reference, Vendor Name, Vendor, URL,
(빈 열),
배부기준
```

맨 앞 열의 헤더명은 (예전 버전과 달리) **`본사/법인`**이다 — 계정구분상의 `구분`(대계정 분류) 열과
헤더명이 겹치지 않도록 명시적으로 구분한 것이다. raw 시트명이 `본사_`로 시작하면 "본사", `법인_`로
시작하면 "법인"이 들어간다 (단, 3단계에서 보고용이 `주재원`인 행은 `법인`으로 재기재된다 — 아래
3단계 규칙 참고).

`URL` 열(33번째) 다음 한 칸(34번째)은 비워 두고, 35번째 열에 `배부기준`을 둔다. 이 빈 칸 구조는
사용자가 명시적으로 요청한 레이아웃이다.

## 1단계 핵심 규칙 (raw 결합, 사용자와 함께 확정한 사양)

1. **시트 결합**: raw 파일의 모든 시트를 하나의 "edit" 시트로 합친다. 각 시트는 컬럼 구성이 동일해야 하며
   (Company Code ~ URL, 19개 컬럼), 컬럼 구성이 다른 시트는 자동으로 건너뛴다.
2. **소계 행 제외**: Company Code가 빈 행은 시트 내 소계/합계 행이므로 결합 대상에서 제외한다.
3. **본사/법인 열**: 맨 앞에 추가. 시트명이 "본사_"로 시작하면 "본사", "법인_"로 시작하면 "법인".
4. **환율 반영**: "Amount in local currency" 열 오른쪽에 "Currency"(해당 월 평균환율), "Amount(KRW)"
   (`=Amount in local currency * Currency` 수식) 열을 추가한다. 환율은 raw 데이터의 Posting Date에서
   가장 많이 등장하는 연/월을 기준으로, 같은 작업 폴더(또는 상위 폴더)의 "환율" 서브폴더에 있는
   "환율 추이(...).xlsx" 파일(가장 최근에 수정된 것) → "환율추이" 시트에서 해당 월 "평균" 값을 통화별로
   가져온다. KRW는 환율 1로 고정. **JPY, VND는 환율추이 시트에 100단위 기준으로 기재되어 있으므로
   (예: 100엔당 몇 원), 시트에서 읽은 값을 100으로 나눈 뒤 1단위 환율로 edit 시트에 반영한다** (다른
   통화는 그대로 사용). 이 로직은 1단계(build_edit_file.py)와 4단계 조정 전표의 "당월환율기재"
   (add_manual_adjustments.py)에 동일하게 적용된다.
5. **합계 행**: 1행에 Amount in doc. curr., Amount in local currency, Amount(KRW) 세 열의 합계를
   `SUBTOTAL(109, ...)` 수식으로 넣는다 (SUM이 아닌 이유: 자동필터로 화면에 보이는 행만 합산되게 하려고).
6. **헤더 스타일**: 2행이 헤더. raw 파일에 원래 있던 컬럼은 밝은 회색(FFDDDDDD), 이 스킬이 새로
   추가한 컬럼은 더 진한 회색(FFA6A6A6)으로 구분한다. 볼드는 쓰지 않는다. **이 "원본 컬럼 vs 새로
   추가한 컬럼" 구분 규칙은 1단계·2단계·3단계에서 추가되는 모든 컬럼에 항상 적용한다** (2단계에서
   추가되는 Company/Cost Ctr Name/대조직/배부조직/보고용/보고용(re)/소계정/대계정/대계정(re)/구분/분류,
   3단계에서 추가되는 배부기준 모두 진한 회색 헤더).
7. **금액 열 서식**: `Amount in doc. curr.`, `Amount in local currency`, `Amount(KRW)` 세 열은
   `#,##0;[Red]-#,##0` 서식(음수는 빨간색 "-1,234"). 데이터 행 전체와 합계 행(1행)에 적용.
8. **기타**: freeze_panes A3, 자동필터 A2:마지막 열/행, Posting Date는 mm-dd-yy.
9. **검증 시트**: "edit" 시트와 별도로 "검증" 시트를 만든다. raw 파일 각 시트의 소계/합계 행
   ("Amount in local currency" 값)의 합과, 실제 결합에 포함된 데이터 행들의 합을 비교해 "일치"/
   "확인 필요"로 표시한다. 소계 행이 아예 없는 시트는 전체 데이터 행 합산 자체가 검증이므로
   "일치(원본에 합계행 없음 - 전체 데이터 행 합산 확인)"으로 자동 처리한다 (수기 확인으로 남기지 않음).
10. **Company Code / Cost Center / G/L Account는 항상 텍스트로 통일**: raw 시트마다 이 세 열을
    숫자로 저장한 경우(예: 본사_HEV 시트는 Cost Center를 숫자로 저장)와 문자로 저장한 경우가 섞여
    있다. 같은 열 안에서 타입이 섞이면 Excel이 숫자는 오른쪽, 문자는 왼쪽으로 자동 정렬해서 같은
    열인데 시각적으로 정렬이 어긋나 보이므로, 값을 결합할 때 이 세 열은 항상 문자열로 변환해서 넣는다
    (예: `2100` → `"2100"`). 4단계에서 조정 전표를 추가할 때도 동일하게 텍스트로 넣어야 한다.

## 2단계 핵심 규칙 (기준정보 반영)

기준정보 파일은 `Costcenter`, `company`, `통합계정`, `계정구분` 4개 시트를 사용한다 (`배부기준`
시트는 3단계에서 사용하고, `배부율` 시트는 사용하지 않음).

1. **Company**: `company` 시트에서 Company Code(Cocd) 기준으로 Company 값을 가져온다. 시트는 "본사"
   섹션(2행 헤더: Cocd/Company, 3~4행 데이터)과 "법인" 섹션(7행 헤더: Cocd/Company/국가/구분/법인장님,
   8행부터 데이터)으로 나뉘어 있다.
2. **Cost Center 상세**: `Costcenter` 시트(3행 헤더: Division/Group/CoCtr/Cost Ctr Name/Category/
   분류/대조직/배부조직/보고용/...)에서 CoCtr(3열, 4행부터)이 실제 Cost Center 코드인 행만 사용해
   Cost Center 기준으로 Cost Ctr Name/대조직/배부조직/보고용을 가져온다. 이 시트는 본사(휴맥스) 전용
   목록이라 해외법인(HUK/HDG/HTR/HUG/HMX/HBR/HSZ 등) 소유의 Cost Center는 원래 여기 없는 게 정상이다
   → 아래 3번 규칙으로 자동 처리된다.
3. **해외법인(법인) 기본값**: Company Code가 `1000`도 `E100`도 아니면서, 해당 Cost Center가
   `Costcenter` 시트에서 확인되지 않는 경우, 보고용 = `'7. 해외법인(법인)'`으로 채우고, 대조직과
   배부조직도 Company 열 값과 동일하게 채운다 (Cost Ctr Name은 공란 유지).
4. **보고용(re)**: 보고용 오른쪽에 추가하는 열. 우선 보고용 값을 그대로 복사하되, 보고용이
   `'6.해외법인(주재원)'` 또는 `'7. 해외법인(법인)'`인 경우 Company 열 값(아래 5번 보정이 반영된
   최종 값)으로 덮어쓴다.
5. **주재원 Company 보정**: `배부조직` 값에 `'주재원'`이라는 문자열이 포함된 경우(예: `HSZ_주재원`,
   `HUK_주재원`, `HJP(주재원)`), Company 열 값을 대조직 값으로 덮어쓴다. **이 보정은 4번(보고용(re))과
   아래 7번(4대보험료 Company 매칭)보다 먼저 적용해서, 이후 로직이 전부 보정된 Company 값을 쓰게 한다.**
6. **G/L Account 상세**: `통합계정` 시트(1행 헤더: G/L/소계정/대계정/분류/...)에서 G/L Account 기준으로
   소계정/대계정/분류를 가져온다.
7. **대계정(re)**: 기본값은 대계정과 동일. `계정구분` 시트의 두 번째 테이블 `[4대보험료]`
   (열 순서: Company/G/L Account/소계정/대계정(원본)/대계정(re), 값은 전부 `'53 4대보험료'`)를
   참고해서, Company가 `'All'`인 행은 G/L Account만 일치하면, `'All'`이 아닌 행은 (5번에서 보정된)
   Company와 G/L Account가 모두 일치하면 대계정(re)를 `'53 4대보험료'`로 덮어쓴다.
8. **구분(계정구분)**: `계정구분` 시트의 첫 번째 테이블 `[구분]`(대계정(re) → 구분 매핑)을 참고해서,
   최종 대계정(re) 값 기준으로 구분을 채운다.

## 3단계 핵심 규칙 (배부기준 반영)

기준정보 파일의 `배부기준` 시트를 사용한다. 이 시트는 상단에 안내 문구 몇 줄이 있고, 그 아래 A열 값이
`Cost Center`인 헤더 행이 나온다 (안내 문구 줄 수가 매월 조금씩 달라질 수 있으므로, 스크립트는 고정
행 번호가 아니라 A열에서 `Cost Center` 문자열을 찾아 헤더 행을 자동 판별한다). 헤더 구성:
`Cost Center, Cost Ctr Name, 대조직, 배부조직, G/L Account, 소계정, 대계정(re), 배부기준, 비고`.

1. **열 생성**: `edit` 시트의 마지막 열(URL, 33번째)에서 한 열 띄고(34번째는 공란) 35번째 열에
   `배부기준` 헤더를 만든다. 재작업으로 이미 `배부기준` 열이 있으면 새로 만들지 않고 그 열을 재사용해
   값만 다시 계산한다.
2. **기본값**: `배부조직` 열 값을 그대로 복사한다.
3. **배부기준 표 조건 순차 적용**: 배부기준 시트 표에서 각 행마다 `Cost Center`/`대조직`/`배부조직`/
   `G/L Account`/`대계정(re)` 중 값이 채워진 열들을 AND 조건으로 삼아 (`Cost Ctr Name`과 `소계정`은
   설명용이라 매칭에 쓰지 않는다), 표를 위에서 아래 순서로 순회하며 조건이 일치할 때마다 배부기준 값을
   그 행의 결과로 **덮어쓴다** (break 없이 끝까지 순회 → 나중에 매칭된 조건이 최종값이 된다). 배부기준
   시트는 일반적인 규칙(예: 대계정(re) 하나만으로 매칭)을 표 위쪽에, 특정 Cost Center+G/L Account
   조합처럼 더 구체적인 예외 규칙을 아래쪽에 두는 방식으로 관리되므로, "나중 매칭 우선"이어야 예외
   규칙이 일반 규칙을 올바르게 덮어쓴다. (표 예시: `G/L Account`가 537170이면 배부기준을 '별도배부율'로,
   `Cost Center`가 105953이면서 `G/L Account`가 537600이면 배부기준을 '공통 100%'로 기재.)
4. **[항상 가장 마지막에 적용, 순서상 5번보다 먼저] 해외법인(법인) 규칙**: 보고용 열 값이
   `'7. 해외법인(법인)'`이면, 위 3번 표 조건 매칭 결과와 무관하게 배부기준 값을 Company 열 값으로
   최종 덮어쓴다.
5. **[항상 가장 마지막에 적용, 4번 다음] Company Code `'E100'` 규칙**: Company Code가 `'E100'`이면
   배부기준을 `'EVCS(국내) 100%'`로 최종 덮어쓰되, 그 행의 대계정(re)가 `'23 감가상각비'`이면
   `'EVCS(국내/해외)'`로 기재한다(배부기준 시트 하단의 `3)` 안내 문구에 순서대로 명시되어 있다).
   `E100`은 2단계 규칙상 항상 국내(본사) 취급이라(Company Code가 `1000`/`E100`이 아닐 때만 해외법인
   기본값이 적용됨) 4번 규칙과 겹칠 일은 없지만, 안내 문구의 나열 순서(해외법인 규칙 다음에 E100
   규칙)를 그대로 반영해 4번 다음에 적용한다.
6. **주재원 → 본사/법인 재기재**: 보고용 열 값에 `'주재원'` 문자열이 포함되어 있으면(예:
   `'6.해외법인(주재원)'`), `본사/법인` 열 값을 `'법인'`으로 재기재한다 (raw 시트명이 `본사_` 접두사라
   1단계에서 "본사"로 채워졌던 것을 교정하는 것). 이 규칙은 배부기준 표와 무관하게 항상 적용한다.

배부기준 규칙(2~6번)은 매월/매분기 기준정보 파일과 함께 바뀔 수 있다(4번·5번처럼 표 하단에 프로즈로
적힌 "항상 마지막 적용" 규칙이 새로 추가되거나 바뀔 수도 있으니, 재작업 때는 표 본문뿐 아니라 표
앞뒤의 안내 문구도 매번 다시 읽는다). 사용자가 "배부기준 시트를 업데이트했으니 반영해줘" 같이
요청하면, 새 기준정보 파일을 다시 읽어 3단계만 재실행하면 된다 (1·2단계를 다시 돌릴 필요 없음 —
아래 "재작업" 항목 참고). 다만 순서(기본값 → 표 조건 → 해외법인 최종 덮어쓰기 → E100 최종 덮어쓰기)나
주재원 규칙 자체를 사용자가 바꿔달라고 하면 이 SKILL.md와 `add_allocation_basis.py`를 함께 업데이트한다.

## 4단계 핵심 규칙 (조정 전표 수기 반영 + 열 그룹화)

`add_manual_adjustments.py`가 담당한다. 기준정보 파일에 `1차 편집` 시트가 없으면 조정 전표 부분은
건너뛰고 열 그룹화만 적용한다 (이번 달은 수기 조정이 없는 정상적인 경우일 수 있음).

**`1차 편집` 시트 구조**: 여러 조정 건이 번호 섹션(예: `1) IT 서비스 비용 조정`)으로 나뉘어 있고,
각 섹션은 보통 (a) 섹션 제목 행, (b) "원전표" 참고용 표(edit 시트에 이미 있는 실제 전표를 보여주는
표, 헤더 행 + 데이터 행), (c) `[조정 전표 추가]` 마커 셀, (d) 실제로 추가해야 하는 조정 전표 표
(마커 바로 아래, 헤더 행 + 데이터 행들) 순서로 구성된다. 헤더/마커는 보통 B열부터 시작하고 A열은
비어 있다 — 스크립트는 `[조정 전표 추가]`라는 문자열이 들어있는 셀을 찾아서 그 위(원전표 표)/
아래(조정 전표 표)를 각각 읽는다. 표 헤더를 읽을 때는 edit 시트와 마찬가지로 URL과 배부기준 사이에
빈 칸이 하나 끼어 있을 수 있으므로, 헤더가 비어 있어도 바로 멈추지 않고 몇 칸은 건너뛰고 계속
읽는다 (연속으로 여러 칸 비면 그때 표가 끝난 것으로 본다).

**지시문 처리**: 조정 전표 표의 셀 값이 실제 값이 아니라 아래와 같은 "지시문"으로 들어있으면 실제
값으로 치환한다.

- Posting Date에 `당월 말일자로 기재` → edit 시트 Posting Date의 최빈 연/월 기준 그 달의 말일.
- Posting Date/Document Number에 `상기 원전표와 동일 기재`(또는 비슷한 문구, "원전표"라는 단어가
  들어있으면 인식) → 같은 섹션의 "원전표" 참고 표 중 이 조정 전표 행과 Cost Center가 일치하는 것을
  먼저 찾고(섹션에 원전표가 하나뿐이면 그걸 그대로 씀), Cost Center/G/L Account/Vendor Name/금액
  (절대값)이 모두 일치하는 edit 시트의 실제 행을 찾아 그 행의 값을 가져온다. **한 섹션 안에 원전표가
  여러 건 있을 수 있으므로(예: 임차료 섹션에 HR실 건과 SCM실 건이 같이 있는 경우), 반드시 조정 전표
  행 자신의 Cost Center로 어느 원전표에 대응하는지 먼저 골라야 한다** — 섹션 전체에 원전표가 하나뿐이라고
  가정하고 아무 조정 전표에나 같은 원전표를 붙이면 엉뚱한 날짜/전표번호가 들어간다. 후보가 0개나
  2개 이상으로 애매하면 자동으로 채우지 않고 콘솔에 경고를 남겨 사용자 확인을 받는다.
- Currency에 `당월환율기재` → 환율 폴더에서 해당 월 평균환율(Document currency 기준)을 가져온다
  (1단계와 동일한 환율 조회 로직 재사용, JPY/VND는 100으로 나눈 값 사용도 동일하게 적용).
- Amount(KRW)에 `당월환율적용 금액 기재` → 값을 직접 넣지 않고 다른 행과 동일하게
  `=Amount in local currency * Currency` 수식으로 채운다 (Z열 수식 패턴을 항상 유지해야 필터/
  합계가 안 깨진다).

**원전표 자체 수정**: `[조정 전표 추가]` 마커 셀에 `및 상기 원전표의 배부기준도 'X'로 수정` 같은
문구가 붙어 있으면, 위에서 찾은 원전표(edit 시트의 기존 행)의 배부기준 값도 X로 함께 수정한다.
원전표를 못 찾았으면 이 수정도 건너뛰고 경고한다.

**Vendor Name 공란 처리**: 조정 전표의 소계정에 `감가상각비` 또는 `상각비`가 포함되어 있으면(예:
사용권자산 감가상각비로 대체하는 분개) Vendor Name은 공란으로 둔다 — 기준정보 표에는 참고용으로
원전표의 Vendor Name이 같이 적혀 있을 수 있지만, 감가상각비 분개 자체는 특정 거래처에 대한 지급이
아니므로 회계상 거래처를 비우는 게 맞다.

**타입 일관성**: 새로 추가하는 행도 Company Code/Cost Center/G/L Account는 1단계와 동일하게 항상
텍스트로 넣는다. 또한 혹시 기존 raw 데이터 쪽에 아직 숫자 타입이 남아있다면(예: 특정 법인 시트만
숫자로 내려오는 경우) 이 단계에서 전체 열을 한 번 더 텍스트로 통일해서, 시트 전체에서 이 세 열의
좌/우 정렬이 어긋나는 셀이 하나도 남지 않게 한다.

**마무리 작업**: 새 행을 추가한 뒤 1행의 `SUBTOTAL(V1/X1/Z1)` 범위를 새 마지막 행까지 늘리고, Z열
수식이 전체 행에서 `=X{row}*Y{row}` 패턴으로 일관되는지 다시 확인한다. 그 다음(반드시 이 Z열 보정
*다음에*) **배부기준 = `'실적 제외'`인 모든 행은 Amount(KRW) 값을 삭제(공란)한다** — 실적 제외
항목은 집계에서 빠져야 하므로 금액을 남겨두지 않는다. 이 규칙은 조정 전표 유무·기준정보 파일의
`1차 편집` 시트 내용과 무관하게 매달 항상 적용한다(4단계 조정으로 새로 추가된 행이든 원래 raw
데이터 행이든 동일하게 적용). 순서를 지키지 않고 Z열 보정보다 먼저 지우면 다시 수식으로 덮어써지므로
반드시 Z열 보정 다음, 열 그룹화 이전에 실행한다. 그 다음 A~B, D~G, L, P, S~Y, AB~AD, AF~AG 열을
그룹화(outline level 1)한다.

새로 추가한 각 행은 스타일(글꼴/테두리/채우기/표시형식/정렬)을 기존 마지막 데이터 행에서 그대로
복사해서 기존 데이터와 구분 없이 자연스럽게 이어지도록 한다.

스크립트는 자동으로 판단하기 애매한 경우(원전표 후보가 0개/2개 이상, 환율을 못 찾음 등)를
`[사용자 확인 필요]` 목록으로 콘솔에 출력한다 — 이 목록이 비어 있지 않으면 반드시 사용자에게
공유하고 직접 확인받는다.

## 4단계 확장 규칙 — 조건부 배부기준/실적 제외 수정 ("예시" 섹션 패턴)

`1차 편집` 시트의 번호 섹션은 서로 다른 두 패턴으로 나타날 수 있다.

**패턴 A — `[조정]` + `[조정 전표 추가]` 마커**: 위에서 설명한 "원전표 참고 표 + 조정 전표 추가 표"
패턴. edit 시트에 새 행을 추가하는 경우다 (`add_manual_adjustments.py`가 자동 처리).

**패턴 B — `[제외]`/`[배부]` + `예시` 마커**: `[조정 전표 추가]` 마커 없이, 섹션 제목 자체에 조건문이
들어있고 그 아래 `예시` 라벨이 붙은 참고용 표만 나온다 (예: `5) [제외] Text '홀딩스 Brand fee' 인 경우
Amount(KRW) 금액 삭제 및 배부 기준도 '실적 제외'로 수정`, `11) [배부] Costcenter '102150 업무지원팀'
이면서 대계정 '27 수도광열비' 인 경우 아래와 같이 배부 기준을 수정한다` + 하위 `-` bullet 여러 개).
이 패턴은 **새 행을 추가하는 게 아니라, edit 시트에 이미 있는 이번 달 실제 거래 행 중 조건에 맞는
행을 찾아 배부기준(및 필요시 Amount(KRW))을 수정하는 것**이다. `예시` 표는 과거 여러 달치 사례를
보여주는 참고 자료일 뿐 그대로 추가하거나 조건 매칭 대상으로 쓰면 안 된다 — 반드시 edit 시트의
**당월** 데이터에서 조건에 맞는 행을 새로 찾는다.

**[필수/실수 재발 방지] 사용자가 특정 섹션(예: "38-39행 추가된 내용")만 콕 집어 언급했더라도,
그 섹션만 반영하고 끝내면 안 된다.** `1차 편집` 시트에는 패턴 A(`[조정 전표 추가]`)와 패턴 B
(`[제외]`/`[배부]` + `예시`) 섹션이 섞여서 여러 번호로 존재하며, 스크립트가 자동 처리하는 건
패턴 A뿐이다. 실제로 2026년 5월 작업에서 사용자가 언급한 항목 하나만 처리하고 "1차 편집 반영
완료"라고 보고했다가, 정작 같은 시트에 있던 패턴 B 섹션 5)~11)번(7개 섹션, 실질적으로 15건의
행 수정)을 전부 누락한 사고가 있었다. 이런 실수를 막기 위해 **매번(사용자가 특정 항목만
언급했든, "반영해줘"라고만 말했든 관계없이) 4단계를 수행할 때는 반드시 아래를 전부 수행한다**:

1. `1차 편집` 시트의 번호 섹션(1\), 2\), 3\)... 및 번호 없이 붙은 `[배부 변경]` 류 추가 항목까지)을
   처음부터 끝까지 목록화한다 — 몇 개 섹션이 있는지, 각각 패턴 A인지 B인지 먼저 전수 파악한다.
2. 목록화한 섹션 전부에 대해 패턴 A는 스크립트로, 패턴 B는 아래 절차대로 inline python으로 직접
   적용한다. "사용자가 언급한 섹션"과 "언급하지 않은 섹션"을 차별하지 않는다.
3. 작업을 마치고 나면, 시트에 있던 섹션 번호 전부 + 각 섹션의 이번 달 매칭 건수를 표/목록으로
   사용자에게 보고한다(0건인 섹션 포함). 사용자가 언급하지 않은 섹션이라도 보고에서 빠뜨리지 않는다.
4. 이 전수 스캔과 보고를 완료하기 전에는 "1차 편집 반영 완료"라고 결론짓지 않는다.

`add_manual_adjustments.py`는 현재 패턴 A만 자동 처리한다. 패턴 B는 매달 문구가 자유롭게 개정될 수
있으므로(예: 조건이 하나 추가되거나 `or` 절이 붙는 식 — 실제로 2026년 5월 작업 중 11번 규칙에
`or Vendor Name '한화호텔앤드리조트'` 조건이 나중에 추가된 사례가 있었다), 스크립트로 고정 파싱하지
않고 **Claude가 매번 섹션 제목/하위 bullet 문구를 직접 읽고 해석해서 inline python으로 적용**한다.
절차:

1. `1차 편집` 시트에서 `[조정 전표 추가]` 마커가 없는 번호 섹션(주로 `[제외]`/`[배부]` 태그)을 찾는다.
2. 섹션 제목과 하위 bullet(`-`로 시작하는 줄)에서 조건을 정확히 파싱한다. 주의할 표현:
   - `A + B` (예: `'마르시스 (또는 Marusys) 정산 + 신정훈'`) → Text에 A와 B가 **모두** 포함(AND).
     괄호 `(또는 X)`는 A 대신 X도 허용하는 OR 대안.
   - `Text가 X 이면서 Vendor Name Y` → Text에 X 포함 AND Vendor Name에 Y 포함.
   - `Text가 X or Vendor Name Y` → 둘 중 하나만 만족해도 조건 충족(OR). 이런 `or` 연결은 기존
     규칙에 나중에 추가되는 형태로 개정될 수 있으니 매번 최신 문구를 그대로 반영한다.
   - `Amount(KRW)가 '44,500,000'` 같은 금액 조건은 **정확히 일치**하는지 비교한다.
   - Cost Center/대계정 조건은 정확히 일치.
3. **[중요/버그주의] Amount(KRW) 비교는 반드시 계산된 실제값으로 한다.** edit 시트의 Amount(KRW) 열은
   `=Amount in local currency * Currency` 수식이 들어있어 openpyxl로 셀 값을 읽으면 수식 문자열
   (`'=X401*Y401'`)이 나오지 계산된 숫자가 나오지 않는다. `ws.cell(...).value == 44500000`처럼 바로
   비교하면 실제로 일치하는 행도 전부 놓친다(실제로 이 실수 때문에 어떤 달 작업에서 금액 조건 규칙
   3건이 처음엔 전부 0건으로 잘못 나온 적이 있다). 반드시 `Amount in local currency` 열 값 ×
   `Currency` 열 값을 직접 곱해서 비교해야 한다.
4. 조건에 정확히 맞는 행을 찾아 규칙대로 적용한다 (`Amount(KRW)` 삭제 + `배부기준` 값 지정, 또는
   `배부기준` 값만 지정).
5. **근접 매칭(조건 일부만 일치) 스캔은 필수다.** `1차 편집` 시트 맨 위 안내문(`계약이 갱신되거나,
   담당자가 바뀌면 Text나 Amount(KRW)는 변동될 가능성이 있음`)대로, 키워드 중 일부만 걸리고 전체 조건은
   불충족인 행이 있으면 반드시 사용자에게 "이번 달은 조건 불충족으로 건너뛰었다"고 알린다 — 계약 갱신,
   담당자 변경 등으로 Text/Amount가 살짝 바뀌어서 놓치는 경우가 실제로 발생한다.
6. CostCenter+대계정 조합처럼 하위 bullet이 여러 개인 섹션(부호(양수/음수) + Text/Vendor 키워드 조합
   패턴)은 **각 bullet이 명시한 경우만 override**하고, 어느 bullet에도 해당하지 않는 행은 3단계에서
   이미 계산된 기본값(배부기준 표 매칭 결과)을 그대로 둔다 — bullet들이 전체 경우의 수를 다 덮는다고
   가정하지 않는다.
7. 모든 조건부 규칙 적용이 끝난 뒤, 표준 마무리 규칙(배부기준=`'실적 제외'`인 모든 행 Amount(KRW) 삭제)을
   전체 스캔으로 한번 더 방어적으로 적용한다(개별 규칙에서 이미 지웠어도 누락 방지 차원).
8. 이 조건부 규칙들은 4단계 전체를 처음부터 다시 돌릴 필요 없이 **현재 `edit_{월}월.xlsx`에 직접
   적용**하면 된다(패턴 A의 `[조정 전표 추가]`처럼 새 행을 추가하는 게 아니라 기존 행 값만 바꾸는
   것이라 중복 위험이 없고, 같은 값으로 재적용해도 멱등적이라 여러 번 실행해도 안전하다).
9. 사용자가 "1차 편집 시트 업데이트했어, 다시 확인해서 반영해줘" 라고만 말해도, 패턴 A(조정 전표
   블록)뿐 아니라 패턴 B(조건부 규칙) 섹션도 처음부터 끝까지 다시 훑어서 문구가 바뀌었거나 새로
   추가된 섹션이 없는지 확인한다 — 사용자는 어느 패턴이 바뀌었는지 구분해서 말하지 않는 경우가 많다.

## 헤더 검증

2단계 스크립트는 참조 시트를 읽기 전에 각 시트의 헤더가 예상과 일치하는지 assert로 확인한다
(`company` 시트의 Cocd/Company, `Costcenter` 시트의 CoCtr/Cost Ctr Name/대조직/배부조직/보고용,
`통합계정` 시트의 G/L/소계정/대계정/분류, `계정구분` 시트의 [구분]/[4대보험료] 테이블 헤더). 3단계
스크립트도 `배부기준` 시트의 헤더(Cost Center/대조직/배부조직/G/L Account/대계정(re)/배부기준)를
assert로 확인한다. 4단계 스크립트는 edit 시트에 필요한 열(Posting Date/Document Number/Cost Center/
G/L Account/Currency/Amount in local currency/Text/Vendor Name/배부기준/소계정)이 다 있는지 확인하고,
`1차 편집` 시트가 아예 없으면 조정 전표 부분만 건너뛰고 열 그룹화는 그대로 진행한다(에러로 멈추지
않는다 — 이번 달은 조정 전표가 없는 정상적인 경우일 수 있으므로). 그 외 불일치하면 스크립트가
에러로 멈춘다 — 기준정보 파일의 시트 구조 자체가 바뀐 것일 수 있으므로 사용자에게 알린다.

## 중복 키 / 미매칭 처리

- `Costcenter`, `통합계정` 시트에 같은 키(CoCtr, G/L)가 두 번 이상 등장하면 **첫 번째 값**을 사용한다
  (VLOOKUP의 기본 동작을 모방). 값이 서로 다른 충돌이 있으면 콘솔에 출력하니, 사용자에게 알려서
  기준정보 파일 정리가 필요한지 확인받는다.
- Company Code/Cost Center/G/L Account가 기준정보에서 끝내 확인되지 않으면 해당 파생 열은 공란으로
  두고 콘솔에 목록을 출력한다. Cost Center 미매칭은 해외법인 코드라면 3번 규칙으로 자동 커버되므로
  정상이지만, G/L Account 미매칭은 기준정보 파일(통합계정 시트)에 계정이 아예 등록 안 된 것이므로
  발견되면 사용자에게 등록을 요청한다.
- 3단계 배부기준 표 조건은 매칭 여부와 관계없이 항상 최소 "기본값(배부조직 복사)"이 채워지므로 공란이
  남지 않는다. 스크립트는 표 조건 규칙별 매칭 건수를 콘솔에 출력하니, 0건인 규칙이 이번 달 데이터에
  해당 사례가 없어서인지 확인하고 이상하면 사용자에게 알린다.

## 실행 방법

1. 스킬 폴더의 `scripts/build_edit_file.py`, `scripts/add_reference_cols.py`,
   `scripts/add_allocation_basis.py`, `scripts/add_manual_adjustments.py`를 `/tmp/`로 복사한다.
2. **1단계** — raw 결합. `--output`은 작업 폴더 안의 영문/숫자 임시 파일명으로 지정한다
   (이유는 아래 "작업 폴더 저장 시 주의사항" 참고).

```bash
python /tmp/build_edit_file.py \
  --raw "raw 파일 전체경로" \
  --fx-folder "환율 폴더 전체경로" \
  --output "작업 폴더 전체경로/_tmp_base_edit_{월}월.xlsx"
```

3. **기준정보 파일 탐색**: 같은 작업 폴더(또는 상위 폴더)에서 `기준정보_{월}월.xlsx` 또는
   `기준정보*.xlsx` 패턴의 파일을 찾는다(가장 최근 수정 파일 우선). 못 찾으면 사용자에게 파일 첨부나
   위치를 요청한다 — 2·3단계 없이 1단계 결과만 내놓지 않는다.
4. **2단계** — 기준정보 반영. `--edit`에는 **반드시 2번에서 만든 1단계 결과(방금 새로 만든 파일)**를
   넣는다. `--output`도 작업 폴더 안의 다른 임시 파일명으로 지정한다.

```bash
python /tmp/add_reference_cols.py \
  --edit "작업 폴더 전체경로/_tmp_base_edit_{월}월.xlsx" \
  --ref "기준정보 파일 전체경로" \
  --output "작업 폴더 전체경로/_tmp_edit2_{월}월.xlsx"
```

5. **3단계** — 배부기준 반영. `--edit`에는 **반드시 4번에서 만든 2단계 결과**를 넣는다. `--output`은
   3단계 결과용 다른 임시 파일명으로 지정한다 (아직 최종 파일명으로 바꾸지 않는다 — 4단계가 남아있다).

```bash
python /tmp/add_allocation_basis.py \
  --edit "작업 폴더 전체경로/_tmp_edit2_{월}월.xlsx" \
  --ref "기준정보 파일 전체경로" \
  --output "작업 폴더 전체경로/_tmp_edit3_{월}월.xlsx"
```

6. **4단계** — 조정 전표 수기 반영 + 열 그룹화. `--edit`에는 **반드시 5번에서 만든 3단계 결과**를
   넣는다. `--ref`는 2·3단계와 같은 기준정보 파일(`1차 편집` 시트가 같은 파일 안에 있다). `--fx-folder`도
   1단계와 같은 환율 폴더(당월환율기재 지시문 처리에 필요). `--output`을 최종 임시 파일명으로 지정한
   뒤, 완료되면 최종 한글 파일명으로 `mv`한다.

```bash
python /tmp/add_manual_adjustments.py \
  --edit "작업 폴더 전체경로/_tmp_edit3_{월}월.xlsx" \
  --ref "기준정보 파일 전체경로" \
  --fx-folder "환율 폴더 전체경로" \
  --output "작업 폴더 전체경로/_tmp_edit_{월}월.xlsx"

mv "작업 폴더 전체경로/_tmp_edit_{월}월.xlsx" "작업 폴더 전체경로/edit_{월}월.xlsx"
rm -f "작업 폴더 전체경로/_tmp_base_edit_{월}월.xlsx" "작업 폴더 전체경로/_tmp_edit2_{월}월.xlsx" \
      "작업 폴더 전체경로/_tmp_edit3_{월}월.xlsx"
```

- `--raw`: 사용자가 첨부한 raw 데이터 파일. 파일명이 아니라 데이터 안의 Posting Date로 대상 월을
  자동 판단하므로 파일명이 달라도 상관없다.
- `--fx-folder`: raw 파일과 같은 작업 폴더 안의 "환율" 서브폴더. 못 찾겠으면 사용자에게 물어본다.
- `--ref`: 3번에서 찾은 기준정보 파일 (2단계와 3단계 모두 같은 파일을 쓴다 — `배부기준` 시트가 같은
  파일 안에 있기 때문).
- `--output`(각 단계): **영문/숫자 임시 파일명**으로, 반드시 최종 목적지와 같은 폴더 안에 만든다.
  최종 파일명(`edit_{월}월.xlsx`)은 실행 후 같은 폴더 안에서 `mv`로 이름만 바꿀 때 붙인다.

1단계 스크립트는 콘솔에 대상 연/월, 사용한 환율 파일명, 결합된 행 수, 시트별 합계 검증 결과를 출력한다.
2단계 스크립트는 콘솔에 헤더 검증 통과 여부, 매핑 충돌, 미매칭 Company Code/Cost Center/G/L Account
목록, 해외법인(법인) 건수, 보고용(re) 대체 건수를 출력한다. 3단계 스크립트는 콘솔에 배부기준 표 헤더행
위치, 로드된 조건 규칙 건수, 조건별 매칭 건수, 해외법인(법인) → Company 값 최종 대체 건수,
Company Code 'E100' → 배부기준 최종 대체 건수(그 중 '23 감가상각비' → 'EVCS(국내/해외)' 건수), 주재원 →
본사/법인='법인' 변경 건수를 출력한다. 4단계 스크립트는 콘솔에 조정 전표 블록 건수, 사용한 환율 파일명,
추가된 행 수, 원전표 배부기준 수정 건수, 그리고 자동으로 판단하기 애매했던 항목의 `[사용자 확인 필요]`
목록을 출력한다. 넷 다 확인해서 이상이 있으면 사용자에게 알린다.

## 재작업(기준정보 업데이트 등) 시

- **1·2단계에 영향을 주는 변경**(Costcenter/company/통합계정/계정구분 시트 변경, raw 데이터 자체
  변경 등)이면 **1단계부터 다시 실행해서** "깨끗한" base 파일을 새로 만들고, 그 위에 2·3단계를
  순서대로 적용한다. 이미 2·3단계까지 끝난 `edit_{월}월.xlsx`를 `add_reference_cols.py`의 `--edit`
  인자로 다시 넣지 않는다 — raw 재결합 없이 이미 채워진 결과 위에 또 채우면, 특히 헤더 처리 방식에
  변경이 있었던 경우 컬럼이 밀리거나 값이 잘못 덮어써질 위험이 있다.
- **배부기준 시트만 바뀐 경우**(가장 흔한 케이스 — 사용자가 "배부기준 업데이트했어, 반영해줘"라고
  요청)에는 1·2단계를 다시 돌릴 필요 없다. 다만 **3단계를 다시 돌리면 100% 확률로 4단계 결과가
  깨진다** — 3단계는 edit 시트의 모든 행(4단계로 추가된 `[Manual]` 행 포함)을 표 조건/기본값으로
  일괄 재계산하므로, 4단계에서 넣었던 값들이 전부 덮어써진다: (a) `[조정 전표 추가]` 표에 문자 그대로
  적혀 있던 배부기준 값, (b) "원전표 자체 수정" 지시로 원본 행에 넣었던 배부기준, (c) 패턴 B(조건부
  배부기준/실적 제외 수정) 스크립트로 직접 반영했던 값 전부. 실제로 어느 달 작업에서 이 순서를 안
  지키고 3단계만 조용히 재실행했다가 수기 조정분이 전부 표 기본값으로 되돌아간 적이 있다. 안전한 순서:
  1. 재실행 전 현재 `edit_{월}월.xlsx`의 `배부기준` 열 값을 행번호별로 백업해둔다(이후 diff로 3단계가
     정확히 무엇을 바꿨는지 확인하는 용도 — 의도한 변경인지 검증할 때 필요하다).
  2. **현재 `edit_{월}월.xlsx`를 그대로 `--edit`으로 넣어** `add_allocation_basis.py`(3단계)를
     재실행한다(`배부기준` 열이 이미 있으면 새로 만들지 않고 값만 재계산하므로 안전).
  3. 3단계 결과 파일에서 Text가 `[Manual]`로 시작하는 마지막 구간(4단계가 추가한 행)을 찾아 삭제한다
     (`ws.delete_rows`).
  4. 그 파일을 `--edit`으로 넣어 `add_manual_adjustments.py`(4단계)를 재실행한다 — `[조정 전표 추가]`
     행이 다시 추가되고, "원전표 자체 수정" 배부기준도 다시 정확히 반영된다(1차 편집 시트가 바뀐 게
     아니므로 내용은 동일하게 재현된다).
  5. 1단계 백업과 새 결과를 행별로 diff해서, 패턴 B(조건부 배부기준) 스크립트로 직접 넣었던 값들이
     또 사라졌는지 확인하고(4단계 스크립트는 패턴 B를 모르므로 거의 항상 사라진다), "4단계 확장 규칙"
     절차대로 패턴 B를 다시 적용한다.
  6. 마지막으로 배부기준=`'실적 제외'`인 행 전체에 Amount(KRW)가 비어 있는지 방어적으로 한 번 더
     확인한다.
- **`1차 편집` 시트(조정 전표)만 바뀐 경우**(사용자가 "기준정보 업데이트했어, 다시 적용해줘"처럼
  조정 전표 내용만 바뀐 경우)에는 1~3단계를 다시 돌릴 필요 없다. 다만 **이미 4단계로 추가해둔
  수기 행을 지우지 않고 `add_manual_adjustments.py`를 또 실행하면 같은 행이 중복으로 쌓인다.**
  그러므로: (1) 현재 `edit_{월}월.xlsx`에서 지난번에 추가된 수기 행들(Text가 `[Manual]`로 시작하는
  마지막 구간)을 먼저 삭제하고, (2) 원전표 쪽에 배부기준을 임시로 덮어썼던 부분이 있다면 그 값도
  기억해두거나(대개 기준정보의 새 지시문으로 다시 정확히 채워지니 크게 문제되지 않는다), (3) 그 상태의
  `edit_{월}월.xlsx`를 `--edit`으로 넣어 `add_manual_adjustments.py`를 재실행한다. 애매하면 1→2→3→4
  전체 재실행이 가장 안전하다.
- **`1차 편집` 시트의 패턴 B(조건부 배부기준/실적 제외 수정, `[제외]`/`[배부]` + `예시` 섹션)만 바뀌거나
  새 섹션이 추가된 경우**에는 1~4단계를 다시 돌릴 필요가 전혀 없다. 새 행 추가가 아니라 기존 행 값만
  바꾸는 작업이므로 **현재 `edit_{월}월.xlsx`에 바뀐/새 조건만 다시 해석해서 직접 적용**하면 된다
  (위 "4단계 확장 규칙" 절차 참고). 주의할 점: 규칙이 바뀌어서 예전에 `실적 제외`로 지웠던
  Amount(KRW)를 다시 살려야 하는 경우, 지운 값은 수식이 아니라 값 자체가 삭제된 것이라 edit 파일
  안에서 복원할 방법이 없다 — 이럴 땐 raw 데이터 쪽 원래 금액(Amount in local currency × Currency)을
  다시 계산해서 채워야 한다.
- raw + 환율 + 기준정보 세 입력에서 매번 새로 만드는 것(1→2→3→4단계 전체 재실행)이 가장 안전하며,
  애매하면 전체 재실행을 우선한다.

## 기준정보 파일이 손상된 zip처럼 읽힐 때

작업 폴더가 클라우드 동기화 폴더인 경우, 사용자가 방금 저장한 파일이 일시적으로 `BadZipFile` 등으로
읽기 실패할 수 있다(내용 자체는 정상인데 동기화 타이밍과 겹치는 것으로 추정). 5~10초 간격으로 3~5회
정도 재시도해본다.

그래도 계속 실패하면, `zip -FF 손상된파일.xlsx --out 복구된파일.xlsx` (필요하면 `yes y | zip -FF ...`로
프롬프트에 자동 응답, `timeout 30`으로 감싸서 무한 대기 방지)로 zip 복구를 시도한다. xlsx는 zip
컨테이너이므로 zip 파일 끝부분(central directory)만 잘려도 openpyxl은 열지 못하지만, `zip -FF`는
로컬 파일 헤더가 남아있는 항목들을 스캔해서 대부분 복구해낸다. 복구 후 반드시
`python3 -c "import openpyxl; openpyxl.load_workbook('복구된파일.xlsx')"`로 정상 로드되는지, 그리고
필요한 시트(Costcenter/company/통합계정/계정구분/배부기준)가 모두 있고 내용이 그럴듯한지(헤더 행,
샘플 데이터 몇 줄) 확인한 뒤 사용한다.

zip 복구로도 계속 실패하면 사용자에게 파일을 다시 저장하거나 채팅에 직접 첨부해달라고 요청한다 —
사용자가 첨부하면 업로드 폴더의 새 사본을 바로 사용할 수 있다.

## 작업 폴더 저장 시 주의사항

사용자의 작업 폴더(Desktop 등 연결된 폴더)는 실제로는 클라우드/로컬 동기화 폴더라서, `/tmp` 등
**다른 장치(device)의 파일을 `mv`나 `cp`로 옮기면** 실제로는 충돌이 없는데도 "File exists" 오류가
나거나, mv/cp가 중간에 끊겨 대상 파일이 0바이트나 손상된 zip으로 남는 경우가 있다(엑셀이 "파일이
손상되었습니다"라며 열리지 않는 문제로 나타난다). 또한 삭제(rm)가 "Operation not permitted"로 막히는
등 예측 불가한 오류도 날 수 있다. 이를 피하려면:

1. **처음부터 각 단계 결과 파일을 작업 폴더 안에, 영문/숫자 임시 파일명으로 직접 만든다** (`--output`을
   작업 폴더 경로로 지정). `/tmp`를 거치지 않으므로 장치 간 이동 자체가 없어진다. (기준정보 파일을
   zip 복구할 때는 예외적으로 `/tmp`에서 작업해도 되지만, 복구된 참조 파일을 스크립트의 `--ref`로
   넘기기 전에 작업 폴더 안으로 한 번 복사해두면 이후 단계에서 안전하다.)
2. 작업 폴더에 동일한 이름의 파일(임시 파일명이든 최종 한글 파일명이든)이 이미 있으면
   `mcp__cowork__allow_cowork_file_delete`로 삭제 권한을 받은 뒤 `rm -f`로 지운다. 삭제 직후
   `ls`가 파일을 여전히 보여줄 수 있는데(캐시 지연), 이는 무시하고 다음 단계로 진행해도 된다 —
   실제 삭제/쓰기 자체는 대개 정상 처리된다.
3. 같은 폴더 안에서 `mv`로 임시 파일명 → 최종 한글 파일명으로 이름만 바꾼다(같은 장치 내 rename이라
   안전하다).
4. **완료 후 반드시 결과 파일이 정상적으로 열리는지 검증한다** — `python3 -c "import openpyxl;
   openpyxl.load_workbook('경로')"` 처럼 실제로 열어봐서 `BadZipFile`/`FileNotFoundError` 등
   예외가 나지 않는지 확인한 뒤에 완료 보고를 한다. 만약 손상되었다면 2~3단계를 다시 반복한다.
5. 위 방식으로도 계속 실패하면(드묾), 최후 수단으로 임시 파일을 그대로 두고 `present_files`로
   사용자에게 전달해 직접 저장하도록 안내한다.

## 완료 후 확인

- 콘솔에 찍힌 1단계 총 행 수가 raw 파일 각 시트의 (행 수 - 헤더 1행 - Company Code 빈 소계행)의 합과
  대략 맞는지 확인한다.
- **"검증" 시트에서 "확인 필요"로 표시된 행이 없는지 확인한다.**
- 2단계 콘솔 출력에서 헤더 검증 assert가 전부 통과했는지, 매핑 충돌·미매칭 목록에 예상 밖의 항목이
  없는지 확인한다 (해외법인 Cost Center 미매칭은 정상, G/L Account 미매칭은 사용자에게 알림).
- 3단계 콘솔 출력에서 헤더 검증 assert가 통과했는지, 조건별 매칭 건수가 그럴듯한지 확인한다.
- 보고용이 `'7. 해외법인(법인)'`인 모든 행이 배부기준 = Company 값과 정확히 일치하는지 확인한다.
- Company Code가 `'E100'`인 모든 행의 배부기준이 `'EVCS(국내) 100%'`(대계정(re)=`'23 감가상각비'`인
  행만 `'EVCS(국내/해외)'`)로 되어 있는지 확인한다.
- 보고용에 `'주재원'`이 포함된 모든 행이 본사/법인 = `'법인'`인지 확인한다.
- 엑셀에서 열어 1행 합계 수식이 정상적으로 계산되는지, 필터를 걸었을 때 합계가 바뀌는지 확인한다.
- `본사/법인`, `Company`, `Cost Ctr Name`, `대조직`, `배부조직`, `보고용`, `보고용(re)`, `소계정`,
  `대계정`, `대계정(re)`, `구분`, `분류`, `Currency`, `Amount(KRW)`, `배부기준` 헤더가 다른 컬럼보다
  진한 회색인지 확인한다.
- `URL` 열과 `배부기준` 열 사이에 빈 열이 하나 있는지(즉 배부기준이 35번째 열인지) 확인한다.
- 금액 세 열(Amount in doc. curr., Amount in local currency, Amount(KRW))의 음수가 빨간색
  "-1,234" 형태로 표시되는지 확인한다.
- 완성된 파일이 openpyxl로 정상적으로 로드되는지(손상 여부) 확인한다.
- 4단계 콘솔 출력에서 `[사용자 확인 필요]` 목록이 있으면 반드시 사용자에게 공유하고 확인받는다.
- 조정 전표로 추가된 행이 있다면, Text가 전부 `[Manual]`로 시작하는지, `Amount(KRW)`가 다른 행과
  동일하게 `=Amount in local currency * Currency` 수식인지 확인한다.
- 1행 `SUBTOTAL(V1/X1/Z1)` 수식의 범위가 조정 전표 추가 후 마지막 행까지 늘어났는지 확인한다.
- 배부기준 = `'실적 제외'`인 모든 행에서 Amount(KRW)가 공란(삭제)인지 확인한다.
- edit 시트에서 A~B, D~G, L, P, S~Y, AB~AD, AF~AG 열이 그룹화(왼쪽에 +/- 접기 버튼)되어 있는지
  확인한다.
- Company Code/Cost Center/G/L Account 세 열에서 숫자 타입과 문자열 타입이 섞여 있는 셀이 없는지
  (즉 같은 열 안에서 좌/우 정렬이 어긋나 보이는 셀이 없는지) 확인한다.
- **[필수, 생략 불가] `1차 편집` 시트의 번호 섹션을 처음부터 끝까지 전수 확인했는지 스스로 재점검한다.**
  사용자가 특정 섹션만 콕 집어 언급했더라도, 언급하지 않은 섹션까지 전부 포함해서 시트에 있는 모든
  패턴 A/패턴 B 섹션의 번호, 태그, 이번 달 매칭 건수를 목록으로 정리한다. 이 목록을 만들지 않고
  "1차 편집 반영 완료"라고 보고하지 않는다.
- `1차 편집` 시트에 패턴 B(`[제외]`/`[배부]` + `예시`) 섹션이 있었다면, 위에서 정리한 목록을 바탕으로
  섹션별 이번 달 실제 매칭 건수가 몇 건인지, 근접 매칭인데 조건 불충족으로 건너뛴 행은 없는지 사용자에게
  공유한다(0건인 섹션이 있으면 이번 달은 해당 사례가 없어서인지 확인이 필요하다고 알린다). 사용자가
  언급하지 않은 섹션이라고 해서 이 보고에서 빠뜨리지 않는다.
- 완성된 파일은 사용자의 작업 폴더에 저장하고 공유한다.

## 이 스킬 자체를 업데이트할 때

사용자가 "fc-1 스킬 업데이트해줘" 같이 이 스킬 자체의 수정을 요청하면, "이 세션에서는 스킬을 수정할 수
없다"고 거절하지 않는다. 대신 skill-creator 스킬을 사용해서 다음 순서로 진행한다.

1. 설치된 스킬 폴더(읽기 전용)를 쓰기 가능한 임시 위치로 복사한다.
2. 복사본의 SKILL.md를 요청받은 내용으로 수정한다.
3. `scripts/package_skill.py`로 수정한 폴더를 `.skill` 파일로 패키징한다.
4. `present_files`로 사용자에게 전달하고, 사용자가 파일 카드의 'Save skill' 버튼을 눌러 직접
   설치(업데이트)하도록 안내한다.

설치된 스킬 파일 자체를 직접 덮어쓰거나 삭제하려고 시도하지 않는다 (읽기 전용이라 실패한다).
